# Document Intelligence Agent: write-up

Seán Carmody. Repo: github.com/sean-carmody5/axmed-docintel. Model: Claude Sonnet 5.5 for text and pages. Haiku 4.5 compared: a quarter of the cost, 58 against 65 of 66 cases, ten wrong values at high confidence against two. Held-out set, never opened while tuning: Sonnet 63 of 66. Time: well past the 4 to 6 hour box, stated honestly in the agent log.

**Architecture.** Every file becomes one neutral `Document` (text, optional page images, flags, children for attachments), chosen by content sniffing, not file name. One schema-driven extraction runs over all of them and must quote the text each value came from. Code then computes confidence per field from independent signals, reconciles lines across suppliers and across copies of the same quotation, writes the table, and stops at a review page where a person decides and corrects each line with the source beside it. `approve` resumes the run and writes `approved.csv`. Format knowledge lives only in loaders; supplier knowledge lives nowhere; the prompt names nothing from any file we hold.

**Extensibility.** A new format is one loader registered on a media type (`src/docintel/ingest/`); nothing downstream changes, and the Word and Excel loaders are the built demonstration. A new supplier is nothing: there is no supplier code to write, and the synthetic set proves it with 20 invented suppliers. A new customer system reads `approved.csv` or `review.sqlite`, or replaces the `promote` node, the one stub in the graph. A new model is a `provider:model` string.

**Framework.** LangGraph for orchestration only: fan-out per document with retries, SQLite checkpoints so a run resumes after a crash, and the review stop as a first-class interrupt that `approve` resumes with the reviewer's decisions. LangChain for the model call only: structured output against a Pydantic schema and provider swap. Everything that determines quality (loaders, grounding, checks, confidence, reconciliation, the page) is plain Python. Cost: version churn pinned by a lockfile, a retry policy that once hid a malformed recording as a crashed batch until failures became flagged records, and the interrupt's resume semantics, which took a test to pin down.

**Structured versus natural language versus images.** JSON and spreadsheets reach the model as themselves. Email arrives as body text with each attachment a document of its own, and the prompt treats a later correction as the value that wins, keeping both. Scans and photos go through the same schema after a transcription step, with an independent OCR pass (RapidOCR, measured against Tesseract on our degraded scans) giving a second reading. The first live run showed why that second reading matters: on scans the model's own transcript cannot vouch for the model, and ten values were wrong at high confidence. Checking names, INN and strength against the OCR reading, as prices already were, brought that to two, both a cropped photo where both readers read the same digit.

**Uncertainty.** Confidence is never asked of the model. Each value is checked: quote found in the document, value found in the quote, arithmetic holds, codes and dates plausible, OCR agrees, duplicate copy agrees. Every deduction is recorded with a reason the page shows. A derived unit price inherits the weaker of its inputs. A missing essential field scores zero, not nothing. The page marks a line red when it cannot be priced as it stands, amber when a value was reached in a way worth a look, and nothing when every key value is in the document word for word. Text addressed to automated readers is flagged and ignored; four planted injections are caught, none of the clean documents trigger.

**Production.** Cost, from recorded tokens: about 8 cents a document on Sonnet 5.5 and 2 on Haiku 4.5 (prices assumed, see evals/reports/cost.md); output tokens dominate because every field carries an evidence quote. Recorded extractions replay for free, so evaluation never pays twice. Latency: the pack of eight runs in 76 seconds with four documents in flight; concurrency is a setting. Monitoring: LangSmith tracing is one variable; the scorer's calibration number (wrong at high confidence) is the metric to alarm on. Regulated data: the model is a config string, so Bedrock or Vertex under a data-processing agreement, or an open-weight model in the organisation's own environment (Qwen VL first for scans), is the swap; the OCR pass is already local. Human-in-the-loop: the page exists, with corrections and an audit of both values; next is decide-and-advance and pointing at the exact spot on the scan a price was read from, using the OCR word boxes.

**CI/CD and infrastructure.** Every push runs lint, types, the synthetic set regenerated and compared with the commit, 411 offline tests, then the whole synthetic set through the pipeline and scored with a fail-on-regression flag, and the provided pack through approve. In production: one container, documents fanned out as graph tasks, checkpoints in Postgres instead of SQLite, the review page served behind the organisation's auth, model calls behind a rate-limited queue, and a held-out eval run on every model or prompt change.

**Limitations.** Two readers agreeing on a wrong digit cannot be caught without a third. Handwriting would trip the OCR agreement signal and over-flag. No FX, so cross-currency comparisons are shown as not comparable rather than converted. Tiered prices produce one row at the lowest tier. HEIC photos and Outlook `.msg` are refused with a reason, each one loader away. With more time: the Opus and open-weight comparison with cost per document, a second extraction pass from another family on low-confidence prices, and the OCR-box pointer on the page.

**The suggested data model.** Five fields cannot compare two quotations. Without unit of measure and units per pack, a price per tablet and a price per bottle look alike; without currency and incoterm, a CIF price and an EXW price look alike; without validity and corrections, an expired or superseded price looks current. The schema used here adds those, plus a price basis (stated, derived, tiered, list), evidence per field, and provenance down to the line, and keeps one row per quotation line rather than per document because that is what procurement compares. Still over-simplified: a single price per line hides volume tiers (kept in a side field), the strength of a combination product is a string, and the model has no notion of the buyer's request, so "quoted what was asked" is not checked.
