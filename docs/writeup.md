# Document Intelligence Agent: write-up

Seán Carmody. Repo: github.com/sean-carmody5/axmed-docintel. Model: Claude Sonnet 5.5, with Haiku 4.5 and Opus 5.5 compared. Time: well past the 4 to 6 hour box; the agent log says where it went.

**Architecture.** Every file becomes one neutral `Document` (text, optional page images, flags, children for attachments), chosen by content, not file name. One schema-driven extraction runs over all of them and must quote the text each value came from. Code then computes confidence per field from independent signals, reconciles lines across suppliers and across copies of the same quotation, writes the table, and stops at a review page where a person decides and corrects each line with the source beside it. `approve` resumes the run and writes `approved.csv`. Format knowledge lives only in loaders; supplier knowledge lives nowhere; the prompt names nothing from any file we hold.

**Extensibility.** A new format is one loader registered on a media type in `src/docintel/ingest/`; nothing downstream changes, and Word and Excel are the built demonstration. A new supplier is nothing to write, and the synthetic set proves it with twenty invented ones. A new customer system reads `approved.csv` or the SQLite file, or replaces `promote`, the one stub in the graph. A new model is a `provider:model` string.

**Framework.** LangGraph for orchestration only: fan-out per document with retries, SQLite checkpoints so a run resumes after a crash, and the review stop as an interrupt that `approve` resumes with the reviewer's decisions. LangChain for the model call only: structured output against a Pydantic schema, provider swap, usage per call. Everything that decides quality is plain Python. What it cost: a retry policy that once turned one malformed recording into a crashed batch, until failures became flagged records; a structured-output warning on the newest models, because the strict JSON-schema mode rejects a schema this size; and resume semantics that needed a test to pin down.

**Structured, natural language, images.** JSON and spreadsheets reach the model as themselves. Email arrives as body text with each attachment a document of its own, and a later correction wins while both values are kept. Scans and photos take the same schema after a transcription step, with an independent OCR pass (RapidOCR, measured against Tesseract) as a second reading. The first live run showed why: on scans the model's own transcript cannot vouch for the model, and ten values were wrong at high confidence. Checking names and strengths against the OCR reading, as prices already were, brought that to two.

**Uncertainty.** Confidence is never asked of the model. Each value is checked: quote in the document, value in the quote, arithmetic holds, codes and dates plausible, OCR agrees, duplicate copy agrees. Every deduction carries a reason the page shows. A derived price inherits the weaker of its inputs; a missing essential field scores zero. The page marks red (cannot be priced as it stands), amber (worth a look), or nothing (every key value in the document word for word). Text addressed to automated readers is flagged and ignored; four planted injections are caught, no clean document trips.

**Results.** Synthetic set of 66 cases judged by expected behaviour: Sonnet 65 of 66, no invented lines, two wrong values at high confidence, both one cropped photo where the model and the OCR read the same digit. Held-out seed, never opened while tuning: 63 of 66. Haiku: 60 and 54, four and fourteen silent errors, a quarter of the cost. Cost from recorded tokens: about 8 cents a document on Sonnet, 2 on Haiku; output tokens dominate because every field carries a quote.

**Production.** Recorded extractions replay for free, so evaluation never pays twice. The pack runs in 76 seconds with four documents in flight; concurrency is a setting. Monitoring: LangSmith is one variable; the number to alarm on is wrong-at-high-confidence from a held-out replay on every model or prompt change. Regulated data: Bedrock or Vertex under a data-processing agreement, or an open-weight model in the organisation's own environment (Qwen VL first for scans); the OCR pass is already local. CI runs lint, types, the regenerated synthetic set, 419 offline tests, then the full set through the pipeline and scored with a fail flag. In production: one container, checkpoints in Postgres, the page behind the organisation's auth, model calls behind a rate-limited queue.

**Limitations.** Two readers agreeing on a wrong digit need a third. Handwriting would trip the OCR signal and over-flag. No FX; cross-currency comparisons are shown as not comparable. Tiered prices give one row at the lowest tier. HEIC and Outlook `.msg` are refused with a reason, one loader each. Next: a second extraction pass from another family on low-confidence prices, and pointing at the spot on the scan a price was read from using the OCR word boxes.

**The suggested data model.** Five fields cannot compare two quotations. Without unit and units per pack, a price per tablet and per bottle look alike; without currency and incoterm, CIF and EXW look alike; without validity and corrections, an expired or superseded price looks current. The schema here adds those, a price basis (stated, derived, tiered), evidence per field, and provenance to the line, with one row per quotation line because that is what procurement compares. Still simplified: volume tiers sit in a side field, a combination product's strength is a string, and nothing checks that what was quoted is what was asked for.
