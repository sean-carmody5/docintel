# Document Intelligence Agent: write-up

Seán Carmody. Repo: github.com/sean-carmody5/axmed-docintel. Model: Claude Sonnet 5.5; Haiku 4.5 and Opus 5.5 compared. Time: about 8 to 10 hours against the 4 to 6 hour box; the agent log says where it went.

**Architecture.** Every file becomes one neutral `Document` (text, optional page images, flags, children for attachments), chosen by content, not file name. One schema-driven extraction runs over all of them and must quote the text each value came from. Code computes confidence per field, reconciles lines across suppliers and across copies of one quotation, writes the table, and stops at a review page where a person decides and corrects each line with the source beside it. `approve` resumes the run and writes `approved.csv`. Format knowledge lives only in loaders; supplier knowledge lives nowhere; the prompt names nothing from any file we hold.

**Extensibility.** A new format is one loader registered on a media type in `src/docintel/ingest/`; nothing downstream changes, and Word and Excel are the built demonstration. A new supplier is nothing to write; the synthetic set proves it with twenty invented ones. A new customer system reads `approved.csv` or the SQLite file, or replaces `promote`, the one stub in the graph. A new model is a `provider:model` string.

**Framework.** LangGraph for orchestration only: fan-out per document with retries, SQLite checkpoints, the review stop as an interrupt that `approve` resumes with the reviewer's decisions. LangChain for the model call only: structured output against a Pydantic schema, provider swap, usage per call. Everything that decides quality is plain Python. What it cost: a retry policy that once turned a malformed recording into a crashed batch, until failures became flagged records; Anthropic's strict JSON-schema mode rejects a schema this size, so tool calling carries a warning; resume semantics needed a test to pin down.

**Structured, natural language, images.** JSON and spreadsheets reach the model as themselves. Email arrives as body text with each attachment its own document; a later correction wins and both values are kept. Scans and photos take the same schema after a transcription step, with an independent OCR pass (RapidOCR, measured against Tesseract) as a second reading. The first live run showed why: on scans the model's own transcript cannot vouch for the model, and ten values were wrong at high confidence. Checking names and strengths against the OCR reading, as prices already were, brought that to two.

**Uncertainty.** Confidence is never asked of the model. Each value is checked: quote in the document, value in the quote, arithmetic holds, codes and dates plausible, OCR agrees, duplicate copy agrees. Every deduction carries a reason the page shows; a derived price inherits the weaker of its inputs; a missing essential field scores zero. Red means the line cannot be priced as it stands, amber worth a look, nothing means every key value is in the document word for word. Text addressed to automated readers is flagged and ignored.

**Results.** 66 synthetic cases from exact truth, judged by expected behaviour. Sonnet: 65 of 66, no invented lines, two wrong values at high confidence, both a cropped photo where model and OCR read the same digit. Held-out seed, never opened while tuning: 63 of 66. Haiku: 60, four silent errors, twelve invented lines, a quarter of the cost. Opus: 60, five silent errors, four of them a pack size written into the strength, nearly twice the cost. About 2, 8 and 14 cents a document from recorded tokens.

**Production.** Recorded extractions replay for free. Eight documents run in 76 seconds with four in flight. Alarm on wrong-at-high-confidence from a held-out replay on every model or prompt change; LangSmith is one variable. Regulated data: Bedrock or Vertex under a data-processing agreement, or an open-weight model in the organisation's environment (Qwen VL first for scans); OCR is already local. CI: lint, types, the regenerated set, 419 offline tests, the full set scored with a fail flag. Then one container, Postgres checkpoints, the page behind the organisation's auth, model calls behind a rate-limited queue.

**Limitations.** One model call per document: a 480-row catalogue does not fit, and chunked extraction is the next step. Two readers agreeing on a wrong digit need a third. Handwriting would trip the OCR signal and over-flag. No FX. Tiered prices give one row at the lowest tier. HEIC and Outlook `.msg` are refused with a reason, one loader each. Next: a second pass from another model family on low-confidence prices, and the OCR word boxes to point at where a value was read.

**The suggested data model.** Five fields cannot compare two quotations: without unit and units per pack, a price per tablet and per bottle look alike; without currency and incoterm, CIF and EXW look alike; without validity and corrections, an expired or superseded price looks current. The schema here adds those, a price basis, evidence per field and provenance to the line, one row per quotation line because that is what procurement compares. Still simplified: tiers sit in a side field, the boundary between strength and pack size is fuzzy, and nothing checks that what was quoted is what was asked for.
